# Challenge 18 Answer Key — Windows Artifact Hunt

**DO NOT READ BEFORE ATTEMPTING THE CHALLENGE**

## Learning Objectives
- Read a Sysinternals Autoruns export and separate legitimate startup entries from a masquerading one
- Recognize the classic sticky-keys (`sethc.exe`) Image File Execution Options debugger backdoor in a registry export
- Spot a disguised scheduled task using an encoded PowerShell payload
- Correlate a Security event log slice with the persistence mechanisms it's showing exploitation of

## Hints
- `autoruns.csv` has one entry worth a second look, but it isn't what's graded here — treat it as corroborating evidence, not the answer.
- IFEO `Debugger` values are meant for actual debuggers, not `cmd.exe` — any binary you attach a debugger to via this key never runs; the debugger runs instead.
- In `scheduled_tasks.txt`, compare each task's `Author` field and look for one that runs a lot more often than a normal maintenance task would.
- `security_events.csv` around `09:41` ties the registry key to something that actually happened.

## What's planted
Four evidence files under `evidence/`, generated by `evidence/generate_evidence.py`
(stdlib-only, fixed seed 1802, deterministic — re-run it from inside `evidence/`
and commit the regenerated `.csv`/`.txt` files if this challenge ever needs
changing). **The Dockerfile copies only the four data files into the image,
never the generator script** — the generator's source contains the planted
values as literal variables (`MALICIOUS_TASK`, the `WinUpdateHelper` row,
the `sethc.exe` entry), so shipping it to the trainee would hand over the
answer outright.

- `autoruns.csv` (~80 rows) — mostly legitimate startup entries across Run
  keys, services, scheduled tasks, Winlogon Notify, codecs, and browser
  helper objects (OneDrive, Defender NIS, NVIDIA, Realtek, GoogleUpdate,
  Adobe, Zoom, Slack, CrowdStrike, Dell, Citrix, Veeam, etc.), including
  per-user `HKCU\...\Run` duplicates of the per-profile apps (a real Autoruns
  export shows the same entry once per Windows profile that has it
  installed). Three other entries are also dated in September (a new Edge
  auto-launch, a new SentinelAgent deployment, an Adobe Genuine Monitor
  task) so the malicious row's month is no longer the only outlier — only
  its `Publisher: (Not verified) Unknown` is. The one malicious row: `Run`
  key entry `WinUpdateHelper` pointing at
  `C:\ProgramData\Microsoft\svchost.exe` — masquerading as `svchost.exe` but
  running out of `ProgramData`, not `System32`, and unsigned. This is a
  secondary IOC for scenario realism — it isn't part of the graded findings.
- `scheduled_tasks.txt` (34 tasks) — realistic Windows/vendor maintenance
  tasks, including several with a legitimately blank `Author` (e.g.
  `GoogleUpdateTaskMachineUA`, `Adobe Genuine Monitor`) and several with
  legitimately short repeat intervals (5-12 hours), so neither signal alone
  points at the malicious one. The one malicious task,
  `\Microsoft\Windows\SystemHealth\Telemetry`, is the only task that combines
  blank `Author` *and* a sub-hour repeat interval (every 30 minutes) *and* an
  encoded PowerShell download-and-run action — that combination, not any
  single field, is what isolates it.
- `ifeo_registry.txt` (15 subkeys) — a `reg export` of the IFEO key with
  legitimate `CompatibilityFlags`/`MitigationOptions`/`LayerName` shims for
  old software (AutoCAD, SAP GUI, a legacy payroll app, IE, Java, a POS
  client, a kiosk launcher) plus exactly one real `Debugger` value: the
  classic sticky-keys backdoor on `sethc.exe`, set to
  `C:\Windows\System32\cmd.exe`. Any time `sethc.exe` would normally run
  (pressing Shift 5x at the login/lock screen, including over RDP before
  authentication), Windows launches the configured "debugger" instead — an
  unauthenticated SYSTEM-level `cmd.exe`. Deliberately did not add a second
  fake `Debugger` value for difficulty — real environments essentially never
  have more than one, so a second would be a realism regression, not an
  improvement.
- `security_events.csv` (285 rows spanning 06:00-21:00) — realistic
  4624/4634/4672/4625/4688 noise across eight accounts (`jsmith`,
  `administrator`, `svc-backup`, `svc-monitor`, `mgarcia`, `twong`,
  `helpdesk`, `svc-reports`) and varied logon types, plus the unchanged
  three-event chain at its exact original timestamps: a 4624 "RDP logon
  attempt reached the Winlogon secure desktop" at `09:41:52`, a 4688 showing
  `cmd.exe` spawned with `sethc.exe` as its creator process at `09:41:58`
  (confirming the IFEO backdoor was actually triggered), and a 4688 at
  `09:42:31` where that `cmd.exe` launches the `svchost.exe` masquerade from
  `autoruns.csv` — tying all three artifacts into one incident. Filtering to
  `09:4x` returns 17 rows (not just these 3), so the hint's time-window
  filter narrows the search but still requires reading a small, realistic
  slice rather than an instantly-obvious 3-line file.

## Step-by-step fix
1. `docker compose exec app bash`
2. `cat /evidence/ifeo_registry.txt` → the `sethc.exe` subkey with
   `Debugger`="C:\\Windows\\System32\\cmd.exe" stands out next to the benign
   `CompatibilityFlags`/`MitigationOptions` entries around it.
3. `grep -B5 'SystemHealth' /evidence/scheduled_tasks.txt` → the `Telemetry`
   task's blank `Author`, encoded PowerShell action, and 30-minute repeat
   interval mark it as the outlier among named, vendor-authored tasks.
4. `grep '09:4' /evidence/security_events.csv` → the 4688 event chain shows
   `sethc.exe` spawning `cmd.exe`, corroborating that the IFEO key was
   exploited, not just planted.
5. Write to `/root/findings.txt`:
   ```
   IFEO_TARGET: sethc.exe
   IFEO_DEBUGGER: C:\Windows\System32\cmd.exe
   TASK_NAME: \Microsoft\Windows\SystemHealth\Telemetry
   ```

## Validation
Ran `docker compose up -d --build` fresh, confirmed
`docker compose exec app /scripts/score_me.sh` reported `0 / 3` with no
`findings.txt` present. Then ran:
```
docker compose exec app sh -c 'cat > /root/findings.txt <<EOF
IFEO_TARGET: sethc.exe
IFEO_DEBUGGER: C:\Windows\System32\cmd.exe
TASK_NAME: \Microsoft\Windows\SystemHealth\Telemetry
EOF'
```
and confirmed `docker compose exec app /scripts/score_me.sh` reported
`3 / 3` (this caught `score_me.sh` using `grep -qx` on patterns containing
literal backslashes, which BRE misparses — fixed to `grep -qxF`). Torn down
with `docker compose down -v --rmi local` afterward.
